## Historias Técnicas

| Epic / Story ID | Título | Descripción | Criterios de Aceptación | Relacionado con (Epic ID) |
| --------------- | ------ | ----------- | ----------------------- | ------------------------- |
| WS-US-44           | Crear Intento de Pago en Stripe | Como Desarrollador, quiero crear un intento de pago en Stripe a través de una API, para iniciar flujos de pago integrados directos. | Escenario: Crear Payment Intent de Stripe exitosamente<br>Dado que el endpoint "/api/v1/subscriptions/payment-intent" está disponible<br>Cuando se envía una petición POST con los valores de `userId`, `amount` y `currency`<br>Entonces se recibe una respuesta con estado 200 y el cuerpo incluye la clave secreta `clientSecret` para la interfaz de pago. | WS-EP-08 |
| WS-US-45           | Obtener Suscripciones del Usuario | Como Desarrollador, quiero consultar el historial de suscripciones de un usuario a través de una API, para poder renderizar su estado de pagos en su perfil. | Escenario: Obtener listado de suscripciones de forma exitosa<br>Dado que el endpoint "/api/v1/subscriptions/user/{userId}" está disponible<br>Cuando se envía una petición GET para un `userId` existente<br>Entonces se recibe una respuesta con estado 200 y una lista de recursos de suscripción. | WS-EP-08 |
| WS-US-46           | Obtener Plan del Usuario | Como Desarrollador, quiero resolver el plan de servicios activo de un usuario a través de una API, para validar sus límites de uso en otros módulos. | Escenario: Obtener plan de suscripción actual exitosamente<br>Dado que el endpoint "/api/v1/subscriptions/plans/{userId}" está disponible<br>Cuando se envía una petición GET con un `userId` existente<br>Entonces se recibe una respuesta con estado 200 conteniendo los campos de plan actual y el estado activo en el cuerpo. | WS-EP-08 |
| WS-US-47           | Degradación de Plan a Freemium | Como Desarrollador, quiero degradar manualmente o por vencimiento el plan de un usuario a Freemium a través de una API, para suspender los beneficios premium. | Escenario: Cambiar plan del usuario a Freemium de forma exitosa<br>Dado que el endpoint "/api/v1/subscriptions/downgrade/{userId}" está disponible<br>Cuando se envía una petición POST con un `userId` existente<br>Entonces se recibe una respuesta con estado 200 indicando la degradación del plan del usuario. | WS-EP-08 |
| WS-US-48           | Procesar Notificaciones de Stripe mediante Webhook | Como Desarrollador, quiero procesar los eventos de confirmación de pago de Stripe mediante una API de webhook, para activar o extender de forma automatizada las suscripciones de los usuarios. | Escenario: Procesar webhook de confirmación de pago exitosa<br>Dado que el endpoint "/api/v1/webhooks/stripe" está disponible y recibe un evento firmado `payment_intent.succeeded`<br>Cuando se envía una petición POST con la firma correcta en la cabecera `Stripe-Signature` y cuerpo JSON del evento<br>Entonces se recibe una respuesta con estado 200 con valor "Received" y se activa la suscripción del usuario.<br><br>Escenario: Intentar procesar webhook con firma inválida<br>Dado que el endpoint "/api/v1/webhooks/stripe" está disponible<br>Cuando se envía una petición POST con una cabecera `Stripe-Signature` inválida o falsificada<br>Entonces se recibe una respuesta con estado 400 y mensaje "Invalid signature".<br><br>Escenario: Fallo en procesamiento interno del webhook<br>Dado que el endpoint "/api/v1/webhooks/stripe" está disponible y la firma es válida<br>Cuando ocurre un error durante el procesamiento de la lógica de negocio de activación de suscripción<br>Entonces se devuelve un estado 500 para forzar el reintento de Stripe. | WS-EP-08 |
