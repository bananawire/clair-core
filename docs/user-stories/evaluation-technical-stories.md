## Historias Técnicas

| Epic / Story ID | Título | Descripción | Criterios de Aceptación | Relacionado con (Epic ID) |
| --------------- | ------ | ----------- | ----------------------- | ------------------------- |
| WS-US-49           | Registrar Telemetría del Dispositivo | Como Desarrollador, quiero almacenar y evaluar lecturas de sensores de un dispositivo en el borde a través de una API, para registrar la calidad del aire histórica y el estado de salud del hardware. | Escenario: Registrar telemetría exitosamente desde dispositivo de borde<br>Dado que el endpoint "/api/v1/evaluations/telemetry" está disponible<br>Cuando se envía una petición POST con los campos de calidad del aire (`co2`, `temperature`, `humidity`), material particulado (`pm1_0`, `pm2_5`, `pm10`), conectividad, `uptime`, `status` y `healthStatus`<br>Entonces se recibe una respuesta con estado 201 y el recurso de evaluación de telemetría creado en el cuerpo.<br><br>Escenario: Intentar registrar telemetría para dispositivo no existente<br>Dado que el endpoint "/api/v1/evaluations/telemetry" está disponible<br>Cuando se envía una petición POST con un identificador de dispositivo que no existe en el sistema<br>Entonces se recibe una respuesta con estado 404. | WS-EP-09 |
| WS-US-50           | Obtener Historial de Evaluaciones de Telemetría | Como Desarrollador, quiero obtener una lista paginada de registros de telemetría de un dispositivo a través de una API, para permitir la auditoría e inspección de reportes previos. | Escenario: Recuperar historial de telemetría de forma exitosa<br>Dado que el endpoint "/api/v1/evaluations/devices/{deviceId}" está disponible<br>Cuando se envía una petición GET por parte del usuario propietario del dispositivo, especificando los parámetros de paginación `page` y `size`<br>Entonces se recibe una respuesta con estado 200 conteniendo los registros de telemetría del hardware.<br><br>Escenario: Acceder al historial de un dispositivo ajeno<br>Dado que el endpoint "/api/v1/evaluations/devices/{deviceId}" está disponible<br>Cuando se envía una petición GET para un `deviceId` que pertenece a otro usuario<br>Entonces se recibe una respuesta con estado 403. | WS-EP-09 |
| WS-US-51           | Obtener Último Registro de Telemetría | Como Desarrollador, quiero recuperar la lectura de telemetría más reciente de un dispositivo a través de una API, para mostrar el estado instantáneo actual de la calidad del aire. | Escenario: Obtener última lectura de telemetría de forma exitosa<br>Dado que el endpoint "/api/v1/evaluations/devices/{deviceId}/latest" está disponible<br>Cuando se envía una petición GET por parte del propietario del dispositivo<br>Entonces se recibe una respuesta con estado 200 conteniendo el recurso de telemetría más reciente.<br><br>Escenario: Obtener última telemetría de un dispositivo ajeno<br>Dado que el endpoint "/api/v1/evaluations/devices/{deviceId}/latest" está disponible<br>Cuando se envía una petición GET para un `deviceId` ajeno al usuario autenticado<br>Entonces se recibe una respuesta con estado 403.<br><br>Escenario: Obtener última telemetría para dispositivo sin registros<br>Dado que el endpoint "/api/v1/evaluations/devices/{deviceId}/latest" está disponible<br>Cuando se envía una petición GET para un dispositivo del usuario que aún no ha transmitido datos<br>Entonces se recibe una respuesta con estado 404. | WS-EP-09 |
